# Merge Intervals

Given an array of intervals `[start, end]`, merge all overlapping intervals and return the non-overlapping intervals.

**Example**

```
Input:  [[1,3],[2,6],[8,10],[15,18]]
Output: [[1,6],[8,10],[15,18]]
```

---

## Hinglish Explanation

### Step 1: Sorting kyun?

- Agar intervals random order mein hain, toh overlap dhundhna mushkil hai.
- Isliye pehle intervals ko **starting point ke basis par ascending order** mein sort karte hain.
- Sort ke baad, overlap sirf **aas-paas wale intervals** ke beech hi ho sakta hai.

### Step 2: Approach

- Ek `ans` vector banate hain jisme merged intervals store honge.
- Har interval ko `ans` ke **last interval** se compare karte hain.

### Step 3: Do conditions

| Condition | Matlab | Kya karna hai |
|---|---|---|
| `current.start > last.end` | Overlap nahi hai | Current interval ko `ans` mein push karo |
| `current.start <= last.end` | Overlap hai | `last.end = max(last.end, current.end)` |

- Overlap mein starting point wahi rehta hai.
- Sirf ending point ko dono mein se bada wala bana dete hain.

### Step 4: Result

- Saare intervals process hone ke baad `ans` mein merged, non-overlapping intervals mil jate hain.

---

## Interview Style Explanation

First, I sort the intervals in ascending order based on their starting points.

Then, I create an answer vector to store the merged intervals.

I iterate through each interval and compare its starting point with the ending point of the last interval in my answer vector.

There are two possible cases:

1. If the answer vector is empty, or the current interval's starting point is greater than the ending point of the last merged interval, there is no overlap. So I add the current interval to the answer vector.

2. Otherwise, the intervals overlap. In that case, I merge them by updating the ending point to the maximum of both ending points.

After processing all intervals, I return the answer vector.

---

## Basic Code

Isme har case alag likha hai, taaki samajhna easy ho.

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {

        int n = intervals.size();

        sort(intervals.begin(), intervals.end(),
            [](vector<int>& a, vector<int>& b) {
                return a[0] < b[0];
            });

        vector<vector<int>> ans;

        if(n == 0) return ans;

        ans.push_back(intervals[0]);

        for(int i = 1; i < n; i++) {

            int start1 = ans.back()[0];
            int end1 = ans.back()[1];

            int start2 = intervals[i][0];
            int end2 = intervals[i][1];

            // Case 1: Same starting point
            if(start1 == start2) {
                ans.back()[1] = max(end1, end2);
            }

            // Case 2: Same ending point
            else if(end1 == end2 && start2 <= end1) {
                ans.back()[0] = min(start1, start2);
            }

            // Case 3: Current interval is inside previous interval
            else if(start2 >= start1 && end2 <= end1) {
                // No change required
            }

            // Case 4: Partial overlapping
            else if(start2 <= end1) {
                ans.back()[1] = max(end1, end2);
            }

            // Case 5: No overlapping
            else {
                ans.push_back(intervals[i]);
            }
        }

        return ans;
    }
};
```

## Optimized Code

- Upar ke saare overlap cases (1 se 4) ek hi condition mein aa jate hain: `start <= last.end`.
- Isliye code chhota aur clean ho jata hai.

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {

        sort(intervals.begin(), intervals.end());

        vector<vector<int>> ans;

        for(auto &interval : intervals) {

            // No overlap OR first interval
            if(ans.empty() || interval[0] > ans.back()[1]) {
                ans.push_back(interval);
            }

            // Overlapping intervals
            else {
                ans.back()[1] = max(ans.back()[1], interval[1]);
            }
        }

        return ans;
    }
};
```

## Complexity Analysis

| Type | Complexity | Reason |
|---|---|---|
| Time | `O(n log n)` | Sorting mein `O(n log n)`, phir ek linear traversal `O(n)` |
| Space | `O(n)` | Output vector ke liye. Sorting mein implementation ke hisaab se extra space lag sakta hai |

 
## Follow Up Questions (Interviewer May Ask)
 
| Question | Short Answer |
|---|---|
| What if intervals are already sorted? | Skip sorting. Time becomes `O(n)`. |
| What if `[1,4]` and `[4,5]` are given? | Depends on the problem. Here `start <= last.end` merges them into `[1,5]`. Always ask the interviewer. |
| Can we do it without sorting? | Yes, with a sweep line or a map of start/end points, but it still costs about `O(n log n)`. |
| What if intervals come as a stream? | Keep a balanced tree (`set` or `map`) and merge neighbours on every insert. |
| Why sort by start and not by end? | Sorting by start means any overlap can only be with the last merged interval. |
| Can we do it in place? | Yes, use a write pointer on the same array. Space becomes `O(1)` extra, apart from sort. |

## Related Problems (Same Pattern)
 
| Problem | Idea |
|---|---|
| Insert Interval | Add the new interval in three parts: before, overlapping (merge), after. |
| Non-overlapping Intervals | Sort by **end**. Keep the one that ends earliest, remove the rest. Greedy. |
| Meeting Rooms | Sort by start. If any `start < prev.end`, return false. |
| Meeting Rooms II | Min heap of end times, or sweep line with start/end events. |
| Interval List Intersections | Two pointers. Overlap is `max(starts)` to `min(ends)`. |
| Minimum Arrows to Burst Balloons | Sort by end. Shoot at the end, skip all balloons that start before it. |
| Remove Covered Intervals | Sort by start, and by end descending on tie. Track the max end. |
| Employee Free Time | Merge all schedules, then gaps between merged intervals are free time. |

## Tips to Remember
 
- First step is almost always **sort**. Ask yourself: by start or by end?
- Sort by **start** when you want to merge.
- Sort by **end** when you want to pick the maximum number of intervals (greedy).
- Overlap check for two intervals: `a.start <= b.end && b.start <= a.end`.
- After sorting by start, only compare with the **last** interval in the answer.
- While merging, only update the end: `max(last.end, cur.end)`.
- Do not forget the case where one interval is fully inside another. `max` handles it.
- Always clarify touching intervals (`[1,4]`, `[4,5]`): merge or not?
- Empty input and single interval are the first edge cases to test.
- If the problem is about counting how many at the same time, think **sweep line** or **heap**.
- Complexity is almost always `O(n log n)` because of sorting.

## Quick Pattern Checklist
 
1. Are there ranges, meetings, or time slots? Think interval pattern.
2. Sort the data.
3. Walk through once, compare with the previous or last element.
4. Decide: merge,skip, or count
