# 1541. Minimum Insertions to Balance a Parentheses String

**Difficulty:** Medium

**Topics:** String, Greedy, Stack

---

## 1. What is the problem actually asking?

- A string has only `(` and `)`.
- It is balanced if:
  - Every `(` has **two consecutive** `))` after it.
  - `(` comes before its `))`.
- We can insert `(` or `)` anywhere.
- Return the **minimum number of insertions** to make it balanced.

---

## 2. Constraints

- `1 <= s.length <= 10^5`
- `s` has only `(` and `)`.

So we need about **O(n)**. Anything slower will time out.

---

## 3. My first brute-force thought

- Try inserting `(` or `)` at every position.
- Check if the new string is balanced.
- Increase the number of insertions one by one until one works.

---

## 4. Complexity of brute force

- Exponential.
- For `k` insertions: about `(n + k choose k) * 2^k` strings, each checked in O(n).

---

## 5. Why is it too slow?

- With `n = 10^5`, the number of possible strings is huge.
- We test many strings that are clearly wrong.

---

## 6. What work am I repeating?

- After every insertion, I scan the whole string again.
- The same prefix gets checked many times.

---

## 7. What information could I store/precompute?

- While scanning left to right, store:
  - How many `)` are **still needed** (`close`).
  - How many insertions I already made (`open`).

---

## 8. New observation

- Every `(` creates a demand of **exactly 2** closing brackets.
- So I do not need a stack. One counter is enough.
- Two cases make trouble:
  - A `)` comes but no demand is pending, so I must insert a `(`.
  - A `(` comes while only **one** `)` of the last pair was seen, so I must insert a `)`.

---

## 9. Optimized idea

Go left to right with two variables.

| Current char | What to do |
|---|---|
| `(` | If `close` is odd, insert one `)`: `close--`, `open++`. Then `close += 2`. |
| `)` | `close--`. If `close < 0`, insert one `(`: `open++`, `close = 1`. |

At the end, answer = `open + close`.

- `open` = insertions already made.
- `close` = `)` still missing at the end.

---

## 10. Why does it work?

- Each `(` needs exactly `))`, so one number (`close`) tells the full pending demand.
- Fixing a problem right when it appears is always the cheapest fix (greedy).
- Odd `close` before a new `(` means the last pair is broken, and the only fix is one `)`.
- Negative `close` means a `)` has no partner, and the only fix is one `(`.
- Leftover `close` at the end must be paid with `)`.

### Dry run: `s = "(()))"`

| Char | close | open |
|---|---|---|
| `(` | 2 | 0 |
| `(` | 4 | 0 |
| `)` | 3 | 0 |
| `)` | 2 | 0 |
| `)` | 1 | 0 |

Answer = `0 + 1 = 1`.

---

## 11. Complexity

- **Time:** O(n)
- **Space:** O(1)

---

## 12. What clue in the statement should trigger this idea next time?

- "Balanced parentheses" plus "minimum insertions".
- A **fixed ratio** (1 `(` needs 2 `)`), so one counter can replace a stack.
- One pass is enough, because each bad spot has only one cheap fix.

---

## 13. What mistake did I make?

- Treating `)` as a single closing bracket, not a pair.
- Forgetting the **odd `close`** case when a new `(` comes.
- Forgetting to add leftover `close` at the end.
- Setting `close = 0` (not `1`) after inserting `(` for an unmatched `)`.

---

## Solution (C++)

```cpp
int minInsertions(string s) {
    int open = 0;
    int close = 0;

    for (char ch : s) {
        if (ch == '(') {
            if (close % 2 == 1) {
                close--;
                open++;
            }

            close += 2;
        } else {
            close--;

            if (close < 0) {
                open++;
                close = 1;
            }
        }
    }

    return open + close;
}
```
