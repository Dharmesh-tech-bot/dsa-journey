# Two Sum (LeetCode 1)

**Problem:** Given an array `nums` and an integer `target`, return the indices of the two numbers that add up to `target`.

**Difficulty:** Easy

---

## 1. What is the problem actually asking?

- Find 2 different positions `i` and `j` where `nums[i] + nums[j] == target`
- Return the **indices**, not the values
- Exactly one valid answer exists
- Same element cannot be used twice

## 2. Constraints

- `2 <= nums.length <= 10^4`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`
- Only one valid answer
- Answer can be in any order

## 3. My first brute-force thought

- Check every pair `(i, j)` with `j > i`
- If sum equals target, return `[i, j]`

**Pseudocode:**

```
for i from 0 to n-1:
    for j from i+1 to n-1:
        if nums[i] + nums[j] == target:
            return [i, j]
return []
```

**C++ code:**

```cpp
vector<int> twoSum(vector<int>& nums, int target) {
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (nums[i] + nums[j] == target) {
                return {i, j};
            }
        }
    }
    return {};
}
```

## 4. Complexity of brute force

- Time: `O(n^2)`
- Space: `O(1)`

## 5. Why is it too slow?

- Nested loops compare every pair
- For `n = 10^4`, that is about 10^8 checks, which is heavy

## 6. What work am I repeating?

- For each `nums[i]`, I scan the whole array again to find `target - nums[i]`
- The same searching is repeated for every element

## 7. What information could I store/precompute?

- Store values I have already seen, with their indices
- Use a **hash map**: `value -> index`

## 8. New observation

- For each `x`, I only need to know: does `target - x` already exist?
- This is a lookup problem, not a search problem
- Hash map lookup is `O(1)`

## 9. Optimized idea

- Create empty map `seen`
- For each `i, x` in `nums`:
  - `need = target - x`
  - If `need` in `seen`, return `[seen[need], i]`
  - Else store `seen[x] = i`

**Pseudocode:**

```
seen = empty hash map

for i from 0 to n-1:
    need = target - nums[i]
    if need exists in seen:
        return [seen[need], i]
    seen[nums[i]] = i

return []
```

**C++ code:**

```cpp
vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> seen;
    for (int i = 0; i < nums.size(); i++) {
        int need = target - nums[i];
        if (seen.count(need)) {
            return {seen[need], i};
        }
        seen[nums[i]] = i;
    }
    return {};
}
```

## 10. Why does it work?

- Every pair `(a, b)` has one element that comes later in the array
- When I reach the later one, the earlier one is already in the map
- So the pair is always found in a single pass
- Checking before inserting avoids using the same element twice

## 11. Complexity

- Time: `O(n)`
- Space: `O(n)`
- Trade-off: extra memory for faster time

## 12. What clue in the statement should trigger this idea next time?

- "Find a pair that sums to a target"
- "Return indices" (so sorting alone would lose positions)
- Need to answer "have I seen the complement before?"
- Pattern: **complement lookup, use a hash map**

## 13. What mistake did I make?

- Using the same element twice (e.g. `target = 6`, `nums = [3, 2, 4]`, wrongly returning `[0, 0]`)
- Inserting into the map **before** checking the complement
- Returning values instead of indices
- Sorting the array first, which breaks the original indices
